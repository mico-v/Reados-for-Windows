This matrix tracks observable compatibility rather than source-code parity. The nested `MSP/` checkout is a read-only local review/drift input, not a ReadOS source directory, build dependency, Git payload, or package payload. The Rust implementation is clean-room unless a row explicitly names copied or derived material. The committed conformance snapshot and its license evidence live under `conformance/msp-upstream/` so clean ReadOS checkouts and CI do not depend on the nested reference repository.

Status meanings:

- `conformant`: the adopted scope passes the selected upstream evidence with no known deviation.
- `partial`: a useful compatible slice exists, but the upstream contract is broader.
- `deferred`: no implementation evidence exists in the Rust mainline yet.
- `not applicable`: intentionally remains in the ReadOS app/domain layer or outside the selected Windows profile.

## Completed vertical slice: `native_pwd_echo_adoption_v1`

The bounded product-adoption slice is complete:

1. Managed `MspRuntime` remains authoritative for parsing, policy/approval, dry-run, streaming events, terminal result, cancellation projection, and exactly-once product audit; no command-name `HybridHost` was added.
2. Only exact canonical lowercase `pwd` and `echo` execution bodies route through one shared lazy Rust proxy. Case variants fail closed without native load or managed fallback, and host command packs cannot override the protected names in any casing.
3. Native Parse must match original raw input, command name, and explicit-empty-aware arguments and prove one simple command with no operator, redirection, assignment, negation, raw newline, or unquoted ampersand. Execution evidence must contain exactly one matching `Allow` audit and no state change. Missing DLL, parser/evidence drift, binary text incompatibility, and unsupported shapes fail closed.
4. Native audit is not projected a second time. `ls`/`cat`/`help` and PDF/chat/workflow/credential/persistence/WinUI behavior remain managed.
5. The historical no-skip `0.1.0-native-pwd-echo-verified` package gate passes. Its smoke covers real host `pwd`, `echo ''`, and `echo -n reados-native-proxy` with one managed audit each plus direct native `ls`/`cat`.

The synchronous v1 ABI cannot preempt a native call already in flight; cancellation checks only surround the bounded side-effect-free calls. The raw-form guard intentionally rejects raw CR/LF and unquoted expandable ampersands, while quoted or escaped operator literals are verified positive cases. Product override protection belongs to the ReadOS composition path and must not be bypassed with the generic core-override builder.

## Completed vertical slice: `native_abi_v2_handshake_v1`

1. The release DLL exposes seven required exports. `MspAbiInfoV2` is exactly 32 bytes and reports major `2`, minor `0`, contract `0x324D534F44414552`, and capabilities `0xF`.
2. V2 requests and responses use explicit pointer/`ulong` length values, preserve embedded NUL, and never mix v1/v2 result pointers or free exports.
3. Only complete absence of all three v2 exports permits v1 fallback. A partial set, version/size/contract/capability drift, malformed output, or oversize result fails closed.
4. Every native-return path frees exactly once, and invoke/dispose share the same lock. Runtime ABI information is available for package evidence.
5. Parse/Execute/Normalize request caps are 128 KiB/1 MiB/1 MiB and response caps are 16 MiB/64 MiB/1 MiB. The bounded writer stops before reserve/copy and closes the measured 54.5x Parse amplification denial-of-service path.
6. The ABI v2 package gate remains verified. The current full-verifier baseline is Rust 66, Core 69, Hosting 259, App 300, managed total 628, 3/3 real release-DLL operations, the static-CRT binary gate, and a zero-warning/zero-error solution build.

## Completed vertical slice: `native_command_core_registry_v1`

1. Rust `Command`, `Invocation`, `Context`, `Registry`, and `CommandPack` contracts replace hard-coded command enumeration and dispatch.
2. Registration validation, duplicate rejection, unknown lookup, deterministic names/order, pack composition, and registry-derived `help` are covered.
3. Command outputs, bytes, exit codes, diagnostics, audit evidence, state changes, fixtures, ABI behavior, and managed product routing remain unchanged.
4. The 12-case baseline/candidate ABI v1/v2 differential passes against candidate DLL SHA256 `2CFD14246FA963AC284B158903ADC910A782AFEDFEA4EC5F247692BF4613E49A`.
5. The slice adds no commands, streams, sessions, pipelines, processes, mutable filesystem behavior, capabilities, or product `ls`/`cat` routing.

## Next vertical slice: `native_mixed_workspace_read_v1`

1. Add capability-based read-only WorkspaceFS traits and deterministic longest-prefix mount routing with virtual-path rebasing.
2. Define a lifetime-safe bridge to the app-owned virtual workspace using opaque handles and explicit callback ownership, disposal, cancellation, concurrency, and .NET delegate-lifetime rules.
3. Preserve the verified fixed-local-NTFS backend, `VirtualPath`, path sanitization, ABI v2 negotiation/ownership, and managed lifecycle/policy/audit authority.
4. Prove direct, virtual, and mixed reads through focused/differential tests and real-DLL/package evidence before migrating product `ls`/`cat`.
5. Do not add writes, trash, streams, pipelines, sessions, processes, or new command capabilities in this slice.

Then keep the dependency order explicit: `native_stream_core_v1`, mutable WorkspaceFS/trash, pipelines/redirection, exec sessions, and finally external processes plus Windows ConPTY/Job Objects. Each remains a separate release gate. The verified registry, ABI, NTFS/local-drive policy, managed lifecycle authority, and package-smoke isolation must not be weakened.

## Intentional ReadOS domain exclusions

PDF parsing/rendering, document models, chat/provider calls, credentials, workflow orchestration, artifact lineage presentation, workspace-state persistence and WinUI remain in `ReadOS.App`. Rust may expose generic workspace, execution and audit primitives to those features, but it must not absorb their domain implementations or secrets.
